Panther X2 eMMC BOOT / ROOTFS read-only audit
Date: 2026-11-16
Status: sanitized evidence excerpt; not a byte-for-byte original terminal transcript.
Privacy: real MAC addresses, partition UUIDs, and other device-identifying values are intentionally omitted.

Collection context
------------------
- Running system root: TF card /dev/mmcblk0p2
- Running /boot: TF card /dev/mmcblk0p1
- Internal eMMC: /dev/mmcblk1
- eMMC BOOT: /dev/mmcblk1p1 (not mounted)
- eMMC ROOTFS: /dev/mmcblk1p2 (not mounted)
- Access method: e2fsprogs debugfs 1.47.0, read-only inspection
- Extracted files were written to /tmp on the running TF system, not to eMMC.

boot.cmd load sequence
----------------------
1. Read and import armbianEnv.txt from the boot device.
2. Build kernel bootargs.
3. Load uInitrd.
4. Load Image.
5. Load dtb/<fdtfile>.
6. Run booti.

Vendor Storage observation
--------------------------
- Rockchip Vendor Storage magic: DVKR
- Version: 2
- item_num: 1
- item ID: 3
- item size: 12 bytes
- ID 3 is LAN_MAC
- The data contains two GMAC addresses.
- Address bytes and actual addresses are intentionally redacted.

Interpretation boundary
-----------------------
This proves the U-Boot files stored in eMMC ROOTFS are byte-identical to the
Ophub Panther X2 repository files. It does not prove those files are present
in the eMMC raw boot area or were executed during the device's actual boot.
Successful Vendor Storage read by the running U-Boot is also not yet proven.

No eMMC writes, mounts, formatting, flashing, or configuration changes were
performed as part of this audit.

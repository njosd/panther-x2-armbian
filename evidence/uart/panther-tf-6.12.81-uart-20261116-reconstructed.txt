据此：
- `mmcblk0` = 本次使用的 64 GB TF 卡。
- `mmcblk1` = Panther X2 内置 Samsung eMMC（本次识别容量约 29.1 GiB）。
- `mmc2` = SDIO，无线设备。
- 根文件系统由 TF 卡 `mmcblk0p2` 挂载为读写；boot 分区也已挂载。
- 本次片段未见此前另一轮 6.12.81 测试出现的 GPT sector mismatch 或 EXT4/JBD2 I/O write errors。不能把不同启动会话的错误混在一起。
- eMMC 的 runtime-PM 警告及 HS200 时钟提示需要保留跟踪，但当前没有本次 eMMC 读写失败证据。

## 4. Ethernet / PHY（本次网络排障重点）

已辨认的 GMAC 初始化信息：

```text
rk_gmac-dwmac fe010000.ethernet:
  clock input or output? (input)
  TX delay(0x30)
  RX delay(0x10)
  integrated PHY? (no)
  clock input from PHY
  init for RGMII
  User ID 0x30 Synopsys ID 0x51 DWMAC4/5
```

随后有线 PHY 成功绑定并建立物理链路：

```text
rk_gmac-dwmac fe010000.ethernet eth0:
  PHY [stmmac-1:00] driver [RTL8211F Gigabit Ethernet]
  configuring for phy/rgmii link mode
...
Link is Up - 1Gbps/Full - flow control rx/tx
```

结论：
- Linux 已探测 GMAC `fe010000.ethernet`。
- PHY 驱动识别为 RTL8211F。
- PHY/GMAC 已协商到 1Gbps 全双工。
- 因此“网卡驱动完全不存在”或“物理链路没有建立”都不符合本次已见日志。
- 物理链路建立不等于 IP 网络正常；当前尚未看到 DHCP 成功、IPv4 地址或默认路由。

## 7. 下一步：只读网络诊断

在设备当前本地 shell 执行以下命令并完整回传输出。它们只读取状态，不修改网络配置、不重启服务、不安装软件：

```sh
echo '===== LINK / ADDRESS ====='
ip -details -br link
ip -br addr
echo '===== ROUTES ====='
ip route
ip -6 route
echo '===== NETWORK MANAGERS ====='
systemctl is-active NetworkManager
systemctl is-active systemd-networkd
systemctl is-active networking
echo '===== NETWORKMANAGER DEVICE ====='
nmcli device status 2>&1
echo '===== NETWORKMANAGER CONNECTIONS ====='
nmcli connection show 2>&1
echo '===== DHCP / NETWORK LOG ====='
journalctl -b --no-pager | grep -Ei 'NetworkManager|systemd-networkd|dhcp|eth0|stmmac|rtl8211|link is|carrier|no lease|timeout' | tail -n 250
echo '===== INTERFACE COUNTERS ====='
ip -s link show eth0
```

如果 `nmcli` 不存在，保留其错误输出即可，不要安装。拿到结果后按层定位：
1. 接口是否存在、是否 UP、carrier 是否为 1；
2. RX/TX packets 是否增长，有无 RX error/drop；
3. 当前实际启用哪个网络管理器；
4. 是否有 DHCP Discover/Request、Offer/Ack 或明确超时；
5. 是否已有地址但启动横幅未读到；
6. 若接口有 carrier 但 RX 计数为 0，再结合 hEX DHCP/ARP 侧记录判断二层链路与 VLAN/端口问题。

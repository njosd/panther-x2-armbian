# Panther X2 首启网络与 SSH 验收

**本清单是实机验收标准，不代表当前已通过。**

## A. 首次启动前

- 使用独立 TF 卡；确认不是当前系统卡。
- 不执行 eMMC 安装，不运行任何写入 eMMC 的脚本。
- 首启接入现有 LAN，暂不修改 hEX 配置。
- 不把 SSH 密码或私钥写入公开仓库。
- 记录 TF 卡镜像文件名、SHA-256、构建 manifest。

## B. 首次启动

- [ ] Panther X2 从 TF 卡启动进入 Ubuntu 24.04。
- [ ] 实际设备树为 Panther X2 专用 DTB。
- [ ] 识别到实际有线网卡及 PHY。
- [ ] RTL8211F/GMAC 链路协商成功，确认速率和双工状态。
- [ ] DHCP 从 hEX 获得 192.168.x.0/24 网段地址。
- [ ] 路由器邻居/ARP 表项正常，不出现持续 stale/failed。
- [ ] 从 iMac 可以 ping 通 Panther X2。
- [ ] Panther X2 可以访问 LAN 网关。
- [ ] SSH 服务自动启动，iMac 可以通过 LAN 地址登录。
- [ ] 不依赖 UART 完成上述日常管理操作。

## C. 重启与稳定性

- [ ] 正常重启后自动获取 DHCP 地址。
- [ ] 冷断电再上电后自动获取 DHCP 地址。
- [ ] 每次启动后 SSH 自动可用。
- [ ] 连续运行期间无间歇性网络失联。
- [ ] 双向通信和 ARP 状态持续正常。
- [ ] 拔掉 UART 后仍可完成管理与日志查看。

建议至少进行多轮冷启动和重启，并保留每轮启动时间、DHCP 租约、PHY 状态、接口统计、ARP 状态及 SSH 连接结果。

## D. 判定规则

以下情况均不能单独判定网络通过：
- 网口指示灯亮；
- Linux 接口显示 UP；
- PHY 显示 Link detected；
- 曾经成功获取一次 DHCP 地址；
- 只能通过 UART 登录。

只有首次启动、重启、冷启动、双向通信、SSH 和持续稳定性全部通过，才算达到本阶段网络验收目标。

## E. 失败时保留的信息

优先收集而非立即重刷：
- U-Boot 启动日志；
- `ip -br link`、`ip -br addr`、`ip route`；
- NetworkManager 连接状态与日志；
- 内核启动日志中 GMAC、MDIO、PHY、时钟、复位相关信息；
- hEX DHCP lease、ARP/邻居状态；
- iMac 到设备及设备到网关的双向测试结果。

UART 仅作为首次失败时的救援和诊断手段，不作为日常管理方式。

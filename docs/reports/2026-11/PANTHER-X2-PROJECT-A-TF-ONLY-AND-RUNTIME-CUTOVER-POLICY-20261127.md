# Panther X2 项目 A：TF-only 实验边界与真实运行环境切换门（2026-11-27）

- 日期：2026-11-27
- 适用范围：Panther X2 项目 A 全阶段
- 决策性质：用户明确确认的强制项目边界；覆盖此前与本决策冲突的 eMMC 前置门及提前迁移表述
- 实验介质：仅 8GB TF 卡 SU08G（CID `035344535530384780b16ad9b700c15f`）
- 明确排除：64GB 对照卡 SN64G；eMMC 不作为项目 A 的实验、构建输出、rootfs 或数据介质

## 1. 不可违反的总原则

**项目 A 在 TF 阶段完成所有构建产物准备、实机启动、系统运行、硬件激活、网络验证和稳定性验收；在项目 A 的 TF 系统完全通过验收之前，不对 eMMC 执行任何写入或改动。只有系统完全正常后，才进入单独的 eMMC 部署阶段。**

具体要求：

- 所有实验镜像、Kernel/DTB/initramfs、测试 rootfs、日志、测试数据及可写系统状态均放在 SU08G 或 RAM 中。
- 不对 eMMC 分区、文件系统、boot area、IDB/SPL、EXT_CSD、Vendor Storage、启动环境或原系统做写入、格式化、重分区、替换、修复或安装。
- 不把 eMMC 挂载为实验 rootfs、数据盘、日志盘或临时工作区；不得将其作为测试输出目的地。
- 不触碰 SN64G。SU08G 是唯一允许作为项目 A 实验存储介质的 TF 卡；任何写卡仍须遵守逐次介质身份核验和操作授权。
- 现有已验证启动链包含 BootROM/eMMC 前级 SPL，再由 SPL 从 SU08G 读取 U-Boot proper 和启动文件。这是当前硬件启动入口的既有只读依赖，不代表项目 A 可以改动 eMMC；不得为追求 TF 自包含启动而提前改写 eMMC。
- RAM-only 是早期隔离阶段，不是后续网络验证的永久环境；从 RAM-only 切换到 TF 完整用户空间，仍然只使用 SU08G，不改变 eMMC 边界。

## 2. RAM-only 到 TF 完整用户空间的切换节点

切换按以下顺序执行，不跨门：

1. **G4-B build-only 审计完成：** 核对构建结果、对象/符号、DTB 隔离状态、manifest 与哈希。CI 构建成功不等于实机通过。
2. **G4-P runtime gate：** 如经独立风险审查并获得明确授权，在当前 RAM-only 环境完成 IO-domain 受控运行时验证。G4-P 当前仍为 HOLD / NOT AUTHORIZED；本文件不构成 G4-P 操作授权。若该门无法安全放行，先记录阻塞与替代方案，不得绕过或擅自执行。
3. **切换到 TF 完整用户空间：** 前置门通过后，在 SU08G 上准备项目 A 专用完整 Linux 测试 rootfs。该环境提供完成后续诊断所需的工具，例如 ip/iproute2、ethtool、tcpdump、dmesg、lsblk/blkid、mount、debugfs，以及必要的 shell/脚本能力。工具按实际阶段和依赖审查纳入，不因此一次性启用全部硬件或服务。
4. **G5 及后续硬件/网络验证：** 在 TF 完整用户空间中继续按单变量顺序验证 GMAC1、MDIO、RTL8211F、链路、TX/RX、ARP/IP/ICMP、TCP/UDP。每个硬件激活门仍须独立审查和授权；切换用户空间不自动放行驱动 probe、寄存器写入或网络配置。

RAM-only B1/G3/G4 已验证资产必须保留为可回退基线。TF 完整用户空间的 rootfs、启动文件和测试数据与现有系统隔离；不复用、不覆盖 SN64G，不安装到 eMMC。

## 3. “系统完全正常”的 eMMC 部署准入条件

eMMC 阶段不得仅凭一次成功启动或一次网络测试开启。至少满足：

- 项目 A 所需的 Kernel、Panther X2 DTB、rootfs、启动链和构建输入均已锁定版本、commit、配置及 SHA-256。
- SU08G 上可重复完成冷启动/重启；无 kernel panic、启动循环、文件系统错误或关键驱动 probe 异常。
- 板载千兆 Ethernet 的 MAC/MDIO/PHY 链路、真实 TX/RX 与项目 A 计划内的网络协议测试均通过，并有设备日志及独立对端证据。
- 目标系统所需的存储识别、挂载、权限、日志和基础服务行为在 TF rootfs 上验证正常；测试数据完整性可检查。
- 升级、回退、故障恢复及 TF 启动介质损坏后的恢复路径已有书面方案和可验证备份。
- 形成 TF 阶段最终验收报告，逐项标注 PASS / CONDITIONAL / NOT VERIFIED；所有阻塞项关闭或由用户明确接受。
- 用户另行审阅 eMMC 部署方案，明确目标设备、写入区域、备份校验、操作步骤、回退方法和影响范围，并对具体 eMMC 写入操作单独授权。

以上任一条件未满足，继续留在 TF 阶段。即使全部满足，也只是允许进入 eMMC 部署方案评审；不构成自动写入授权。

## 4. 对旧路线表述的处理

本决策覆盖此前将“eMMC pre-Linux 写入安全门通过”设为 TF 实验写入/启动前置条件的旧表述。项目 A 采用现有已验证启动入口，实验数据和系统始终留在 SU08G；eMMC 不作任何主动修改。旧报告中的 eMMC 风险分析保留为历史证据，不再作为 TF 阶段无限扩展的阻塞专题。

本决策也覆盖此前将项目 A 真实运行环境切换描述为仅从 RAM initramfs 启动的表述：早期 RAM-only 继续保留作隔离基线；后续需要完整用户空间时，应在 SU08G TF 上建立独立测试 rootfs，而不是转向 eMMC。
